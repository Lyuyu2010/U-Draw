### 笔迹边缘「锯齿」——实测结论

用户怀疑是笔刷算法或画布分辨率。测下来**都不是**：

1. **笔刷有抗锯齿**。硬笔 6px 的横截面灰阶：`0 → 40 → 255`，有 1px 羽化；软笔 24px 有 8 个灰阶 / 14 个过渡像素。这是 8bit 光栅的正常水平。
2. **锯齿来自显示路径**。`paintEvent` 里原来写的是 `zoom < 2.0` 才开 `SmoothPixmapTransform`，超过 200% 每个文档像素就变成硬方块 —— 266% 下 1 个像素 = 2.66 屏幕像素，硬笔描边看着就是楼梯。
3. 同一笔在 266% 的 A/B 截图：不平滑 = 硬阶梯，平滑 = 连续边缘，肉眼差别就是用户看到的那样。

**改法**：阈值 `200% → 400%`（`SMOOTH_ZOOM_LIMIT = 4.0`），和 PS 的观感对齐 —— PS 也是到 500% 左右才显像素块。原来的「放大时平滑显示」开关保留，含义改成「任何倍率都平滑」。

> 想进一步提质的话，真正有效的是**笔尖超采样**（stamp 按 3× 渲染再降采样）。那是动引擎的活，需要逐笔刷的视觉回归，建议单独排一项做。

### S5 落地说明（四种滤镜 + 预览）

**第一版翻车了**：做了 10 个滤镜，用户反馈「全部效果一模一样、换一个也不变」。
根因是 `QAction.triggered` 会传一个 `checked=False`，把我 `lambda _k=_key:` 里的
默认值**覆盖掉了** —— 每次都在调 `apply_filter(False)`，未知 key 直接原样返回。
单元测试全绿（直接调 `apply_filter("invert")`），菜单这条路一次都没测到。

修法：`lambda checked=False, _k=_key: ...`，用 `checked` 占住第一个位置。
`filters.resolve()` 也让「显示名」能当 key 用，避免同类静默失效。

**最终只留四种**（用户指定）：

| 滤镜 | 参数 | 实现 |
|---|---|---|
| 线稿 | 线条强度 1–10 | Sobel 梯度 → `255 − 梯度`，只改 RGB 不动 alpha |
| 高斯模糊 | 半径 1–40 | 三次方框模糊近似，累积和滑窗，O(像素数) 与半径无关 |
| 像素化 | 块大小 2–40 | 块平均 + `np.repeat` 放大 |
| 黑白 | 对比度 30–300% | 亮度去色 + 绕 128 中灰拉对比度 |

**交互改成「预览 → 应用」**（用户要求，因为实时滤镜太耗性能）：

1. 菜单点一个滤镜 → **画布上直接预览**，选项栏换成「滤镜名 + 参数滑杆 + 取消 + 醒目的蓝色 ✔ 应用」
2. 拖滑杆重算预览，**80ms 防抖**（大画布上不卡手）
3. 预览期间**不动撤销栈**；点「应用」才写一条 `PixelEdit`，所以「取消」是干净的
4. 预览中想干别的（画布上落笔、切工具）→ 弹窗问「应用 / 放弃 / 继续调整」，
   选「继续调整」就把这次操作吞掉
5. Esc = 放弃，Enter = 应用

预览是**直接改图层图像**再 `recompose`，所以图层顺序、不透明度、洋葱皮全都对。

#### 第二轮返工（用户反馈）

| 问题 | 根因 | 修法 |
|---|---|---|
| 切换滤镜就自动应用了 | `open_filter` 里为了「换一个滤镜」，先调了 `_filter_apply()` 把上一个落地 —— 用户根本没点应用 | 引入 `base`（本次预览的原始底图）：换滤镜**只换 key 和参数**，始终基于 base 重算，撤销栈一动不动 |
| 线稿算法不对 | 旧实现是 Sobel → 反相。① 透明图层空白区 RGB 是 0，被当成黑色 → 整片糊掉 ② 柔和笔触只出很淡的一侧边 ③ 粗线变空心双线 | 换「除法/颜色减淡」：先按 alpha 合成到白纸再算亮度，`ratio = gray/模糊(gray)`，再乘增益压深。纯黑平坦区特判成白（否则 0/0 变黑片） |
| 高斯模糊有一圈方框 | 直接拿选区大小去算，边界靠边缘延拓补，模糊把边界像素复制进来看得出来 | 处理区域往外扩 48px 再裁回来，边界用的是真实的邻居像素 |

线稿算法对比见 `docs/screenshots/v3-lineart-algo.png`（左列笔触、右列线稿图，s 越大线越浓）。

#### 第七轮（最终）：阈值改硬切 + 1px 抗锯齿

第六轮的软过渡带（26 个色阶）有两个副作用：
- **软笔刷**会被切出一圈很宽的灰边（用户截图里那个「黑芯 + 灰晕」）；
- 插画的灰调阴影会被半推半就地变成灰斑。

改成**硬切 + 1px 平滑抗锯齿**后，软笔刷是实心黑线、边缘干净，插画也不再花。
对比图 `docs/screenshots/v3-lineart-final.png`（原图 / s=5 / s=6）。

#### 第六轮：边缘 + 暗部阈值 取并集

用户拿真实的浅色插画（粉发/浅肤色）试，**纯阈值只留下丝带和眼睛几块黑斑**，其余全白。
而纯边缘法对实心粗线又会出空心圈。两种语义必须合并：

```
line = max(边缘(归一化 Sobel), 暗部(阈值))
```

- 亮的地方 → 边缘描轮廓（插画的头发丝、脸、蝴蝶结都有线）
- 比阈值暗的地方 → 整块留黑（实心粗线就是实心线，不中空）

实测同一张插画：s=4 线偏淡、**s=6 最平衡**、s=8 头发糊成黑块。默认 6。
对比图 `docs/screenshots/v3-lineart-hybrid.png`。

#### 第五轮：线稿回到「边缘法」，并修掉粉边的真凶（已被第六轮取代）

用户拿导入的插画试：**阈值法把插画糊成黑块**（深色头发整块低于阈值）。
A/B 对比（`docs/screenshots/v3-lineart-ab.png`）结论很明确：

| | 插画 | 手绘笔触 |
|---|---|---|
| 阈值法 | 黑块 ✗ | 浅笔触整个消失 ✗ |
| **边缘法（归一化 Sobel + 加粗 1px）** | 干净线稿 ✓ | 笔触轮廓 ✓ |

所以定稿用边缘法，强度默认 6。

**粉边的真凶**（用户反馈「线稿/黑白边缘还是原色」）：预览写回用的是 `drawImage` 默认的
**SourceOver** —— 滤镜输出带半透明边，原来的颜色就从下面透出来。改成
`CompositionMode_Source`（直接替换）后，残留彩色像素从 257 → **0**。

#### 第四轮：线稿改用「去色 + 阈值」（PS 的做法）（已被第五轮取代）

第三轮的归一化 Sobel 线够黑了，但**方向仍然错**：它描的是「边界」，所以一条实心
粗线会被描出内外两条边、中间变白 —— 空心圈，完全不像线稿。

PS 里做线稿是「去色 + 阈值」：**深的留下变黑、浅的去掉变白**，不是描边。
改过来之后，粗线整条变黑、肤色块直接扔掉，才是线稿该有的样子。

「线条强度」= 阈值高低（100~250，默认 7 档 ≈ 200）。默认值要够高才留得住
40% 不透明度的笔触（合成到白纸后亮度约 197）。

> 教训：先自己启动软件、用真实笔刷画、走真实菜单看结果，再动算法。
> 前三轮都是靠合成图上的数字判断，方向错了也没发现。
> 真机对比图：`docs/screenshots/v3-filters-real.png`

#### 第三轮：线稿换「归一化 Sobel」（已被第四轮取代）

用户反馈「线稿提炼线条还是会出现这样」（笔触仍是一团粉）。查下来是**算法选型**问题：

- 除法/颜色减淡对「柔边 + 低对比」的内容出不来强线 —— 40% 不透明度的笔触，
  `gray/soft` 一直贴着 1，线条永远很淡；
- 更关键的是**半透明笔触的 alpha 限制了线条浓度**：线就算画成全黑，40% 透明度
  合成出来也只有 153 灰，看着就是「糊成一团粉」。

改成：Sobel 梯度 → 按「有内容区域」的 **99 分位归一化** → 乘强度 → 线条处
`alpha = max(原 alpha, line × 255)`。这样半透明笔触也能出实心黑线。
对比图：`docs/screenshots/v3-lineart-v3.png`。

## 一、先说三个盘点结论

在动手之前，对照代码把需求过了一遍，有三件事需要先对齐，否则会白做：

**① 涂抹工具已经有了，第三梯队只需要补「模糊」和「液化」**
路线图写「涂抹、模糊、液化工具」，但 `core.py:1879 SmudgeStroke` 已经是一个相当成熟的实现（线性插值 + 距离落点 + 每步重抓色，注释里记录了四轮调参过程），快捷键 `S` 也在用。第三梯队第 1 项的实际工作量是 **2 个新工具**，不是 3 个。

**② 复制已有、剪切完全没有**
`main_window.py:2494 copy_selection` 已经能复制选区/整层，同时写系统剪贴板；`paste_clipboard` 贴成新图层也通了。但全仓库搜不到 `Ctrl+X` / 剪切 —— 第二梯队第 2 项是「补 3 个动作 + 1 个新基建」，不是从零搭剪贴板。

**③ 参考图窗口、网格、洋葱皮、滤镜：四项全是零**
`grep 参考图 / 网格 / 洋葱 / 滤镜` 在业务代码里没有任何命中。这四项要从零建。

另外有个必须先定死的架构约束：**洋葱皮和网格是「视图层效果」，绝对不能进 `Document.composite`**。因为 `composite` 被 `flatten()`、`export_image()`、PSD 导出直接消费（`core.py:3037` / `4021`），一旦把降透明度或网格线画进合成图，导出的 PNG 就会带着别人的图层和格子。这条约束决定了洋葱皮只能走 canvas 的独立渲染路径。

### 2-1 自由变换进阶：Warp / 网格变形

**目标**：在现有旋转/缩放/翻转之上加扭曲与网格变形。

**现状**：`TransformOp`（3409）只有 `center / w / h / angle / flip`，`transform()` 返回单个 `QTransform`，`render()` 一次性贴图。Warp 不能用一个线性矩阵表达，需要改渲染路径。

**实现**
- `TransformOp` 增加模式：`self.mode = "affine" | "warp"`，`self.mesh = n`（默认 4×4 控制点网格）。
- 网格数据：`self.pts = [[QPointF 偏移]]`，以 `src_rect` 为基准归一化（0~1），这样缩放/旋转后网格跟着走。
- 渲染：遍历每个格子，源四边形 → 目标四边形用 `QTransform.quadToQuad(src_quad, dst_quad, t)` 求单应矩阵，然后 `p.setClipRect(目标四边形)` + `p.setTransform(t)` + `drawImage`。这是标准做法，比逐像素 remap 快一个量级。
- 交互：进 warp 模式后画网格线 + 圆点控制点，拖动点实时重绘；`Alt+拖` 微调相邻点；「重置网格」回退。
- 撤销：沿用 `TransformOp.steps` 的步进机制（`state()` / `set_state()` 扩展为包含 mesh 快照）。
- 风险与兜底：`quadToQuad` 在四边形严重非凸时会退化（矩阵奇异）。处理：限制单点拖拽幅度不超过格宽，并在求逆失败时该格退回双线性贴图。

**验收**：4×4 网格拖动后画面连续无撕裂；推出画布的内容不丢（`ExtEdit` 覆盖）；Ctrl+Z 步进可退；取消变换完全还原。

### 2-2 选区全家桶

**目标**：Ctrl+X 剪切、复制为新图层、剪切为新图层。

**实现**
- 新增 `CompoundEdit`（`core.py`）：持有一个 edit 列表，`undo` 逆序执行、`redo` 正序执行，`label` 可配。这是「剪切为新图层」必需 —— 它同时改了图层结构和像素，必须是**一次** Ctrl+Z 全还原。
- `cut_selection()`：`copy_selection()` 复用（已写剪贴板）→ `clear_area()` 得到 `PixelEdit` → `push`。
- `copy_to_new_layer()`：取选区 bbox → `copy(r)` → 用 `QPainterPath` 生成 Alpha 蒙版 `DestinationIn` 提取 → `add_layer` + `set_ext` → 包 `StructEdit`。
- `cut_to_new_layer()`：上面两步合成 `CompoundEdit`。
- 快捷键：`Ctrl+X` 按现有惯例「菜单里只做展示、实际在 `keyPressEvent` 处理」（`main_window.py:917` 注释说明了原因 —— 避免抢走文字输入框的按键）。

**验收**：剪切后原位置变透明、Ctrl+Z 一次全还原；复制为新图层位置与选区 bbox 一致、Alpha 边缘与选区羽化一致；在图层组内操作不破坏组结构。

### 3-1a 模糊笔

**实现**：新类 `BlurStroke`，结构照抄 `SmudgeStroke`（局部 ROI + `_mask_arr` 遮罩 + numpy）。
- 每步：取落点 ROI → `_box_blur`（391，已有）按半径模糊 → `out = 原图 × (1-kM) + 模糊 × kM` 混回。
- 参数映射：笔刷「力度」→ 混合量 k；「硬度」→ 模糊半径（软笔模糊范围大）。ROI 限制在笔径 + 2×半径，大笔径自动降采样再上采样。
- 复用 `Stroke` 的脏矩形与 `PixelEdit` 撤销，不新造轮子。

### 3-1b 液化

**实现**（分两阶段，先做实时局部版）
- 阶段一（推荐先上）：局部 ROI 逆向映射。笔刷内每个像素按高斯权重沿拖拽向量反向采样（numpy 手写双线性），只重算笔径范围内的区域。相比全局网格，算力低两个数量级，手感接近 PS 的「向前变形」。
- 阶段二（可选）：整层网格位移场 + `QThread` 后台计算，算完合并（路线图原文建议）。只有在用户反馈「要大范围推」时才值得做。
- 风险：反复采样会让像素越糊越软（累积重采样损失）。缓解：始终从「本笔起始快照」采样，而不是从上一帧结果采样。

### 3-2 十个滤镜

**实现**
- 新文件 `filters.py`，**纯函数、无 Qt 控件依赖**（和 `core.py` 一样可移植）：
  ```python
  def gaussian_blur(img: QImage, radius: float) -> QImage
  def sharpen(img, amount) / emboss(img, angle, height)
  def mosaic(img, block) / invert(img) / hue_sat(img, h, s, l)
  def brightness_contrast(img, b, c) / threshold(img, level)
  def posterize(img, levels) / noise(img, amount)
  ```
- 统一流程：`img → numpy → 计算 → QImage`，选区存在时按 `doc.selection` 生成 mask 混合（选区外保持原样），产出 `PixelEdit` 入栈。
- 高斯模糊用两次 `_box_blur` 近似（O(n) 与半径无关），比真高斯快 5~10 倍。
- UI：「滤镜」菜单（`main_window._build_actions` 891）+ 每个滤镜一个参数小对话框（复用 `dialogs.py`）；提供「重复上次滤镜 `Ctrl+F`」。

**验收**：1920×1080 单层高斯模糊 r=20 在 300ms 内；选区外像素零变化（逐像素比对）；每个滤镜都可撤销。

## 五、建议执行顺序

用户给的是「难度梯队」，实际施工建议按**风险与依赖**重排，理由写在右边：

| 序 | 内容 | 理由 |
|---|---|---|
| S1 | 网格 + 洋葱皮 | 同属视图层，共用 canvas 绘制管线，一次改完一起测 |
| S2 | 参考图窗口 | 完全独立，不碰引擎，可并行 |
| S3 | 笔刷 +10 款 | 纯数据，最快的正向反馈 |
| S4 | 选区全家桶 | 日常高频；顺便把 `CompoundEdit` 基建建好，后面滤镜/液化都要用 |
| S5 | 十个滤镜 | 建 `filters.py` + numpy 基建，一次产出 10 个功能，性价比最高 |
| S6 | Warp 网格变形 | 依赖 `CompoundEdit` 与 `ExtEdit`，且要反复调交互 |
| S7 | 模糊笔 | 复用 S5 的模糊核，此时已经调好 |
| S8 | 液化 | 算力最贵、风险最高，放最后，且可只做局部实时版 |
| S9 | 打包 / 文档 / 全量回归 | 版本号 3.0.0、README、使用说明、安装包 |

第一梯队 4 项（S1~S3）完成后就能出一个可发布的 3.0 beta，用户能立刻感知到变化 —— 这是「见效快」的正确用法。

## 六、全局约束（每项都必须遵守）

1. **Undo 栈**：像素改动 → `PixelEdit`/`ExtEdit`；结构改动 → `StructEdit`；组合操作 → `CompoundEdit`。任何直接改 `layer.image` 而不产 edit 的写法都是 bug。
2. **存档兼容**：`manifest.json` 新增字段一律 `get(key, default)`，老 `.pcdraw` 必须能打开。
3. **导出隔离**：洋葱皮、网格、参考图、变换框、蚂蚁线**永远不进** `flatten()` / `export_image()` / `psd_export`。
4. **性能**：纯 CPU 光栅，所有像素运算走 numpy + ROI；单笔操作不阻塞 UI（超过 100ms 的走 QThread）。
5. **测试**：每个功能补一套 `_test_v3_<功能>.py`，格式对齐现有脚本；每轮合并前跑全量 22 套 + 新增套。
6. **版本与文案**：`version_info.txt` / `installer_version.py` / README 徽章 / 使用说明同步到 3.0.0。顺带修正 README 里已过期的数字（写的 102 支笔刷 / 13 分类 / 23 笔型，实测 133 / 17 / 55）。
